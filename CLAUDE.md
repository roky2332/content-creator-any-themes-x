# Content Creator — посты для X (любые темы)

Этот репозиторий — «память» о том, как готовить посты автора для X (Twitter).
Перед любой работой над постом или анимацией ОБЯЗАТЕЛЬНО прочитай нужные файлы из `guidelines/`
и следуй им дословно. Правила автора важнее любых общих представлений о «хорошем посте».

## Файлы правил
| Файл | Когда применять |
|---|---|
| `guidelines/post-format.md` | **Мастер-промпт.** Любой пост: 4 ниши, стиль, хук, структура, визуальное оформление, anti-AI-slop, фактчекинг |
| `guidelines/content-producer.md` | Когда автор присылает исходник (видео, статью, интервью, ссылку): анализ → угол подачи → пост → визуал → источники |
| `guidelines/animations.md` | Только когда автор просит анимацию (AI / Tech): идея, сценарий, раскадровка, тех. параметры 1920×1080, 30 FPS, MP4 |
| `guidelines/quality-control.md` | Всегда — финальная редакторская проверка любого результата перед выдачей |
| `examples/<ниша>/` | Референсные посты автора по нишам. Стиль ниши применять только к этой нише |

## Ключевые правила (кратко, полная версия — в `guidelines/`)
- Посты на английском по умолчанию, если автор не попросил другой язык
- Хук — обычный регистр, никогда не ALL CAPS
- Короткие абзацы по 1-2 предложения, пустая строка между ними
- Без точек в конце строк, без длинных и средних тире (— –), только дефис (-)
- Финал — один короткий вопрос, без вывода после него
- Никогда не выдумывать цитаты, цифры, даты, таймкоды, содержание видео

## Формат выдачи постов автору
- Готовый текст поста всегда присылать внутри блока кода (```text … ```), чтобы его можно было скопировать одной кнопкой
- В блоке только сам пост, без заголовков, пометок и разделителей
- Комментарии, таймкоды для монтажа и замечания по проверке фактов писать вне блока
- Если вариантов поста несколько, каждый в отдельном блоке

## Как работать с репозиторием
1. Когда автор говорит «нужно изменить …» / «запомни …» — внеси правку в нужный файл
   в `guidelines/`, добавь запись в `CHANGELOG.md`, закоммить и запушь.
2. Не выдумывай правила, которых автор не давал. Если что-то не описано — спроси.
3. Когда автор присылает референсные посты — определи нишу и сохрани в `examples/<ниша>/`.
4. Если автор хвалит пост — предложи сохранить его в `examples/`.
