# Content Creator — посты для X (любые темы)

Этот репозиторий — «память» о том, как готовить посты автора для X (Twitter).
Перед любой работой над постом или анимацией ОБЯЗАТЕЛЬНО прочитай нужные файлы из `guidelines/`
и следуй им дословно. Правила автора важнее любых общих представлений о «хорошем посте».

## Файлы правил
| Файл | Когда применять |
|---|---|
| `guidelines/post-format.md` | **Мастер-промпт.** Любой пост: 5 ниш, стиль, хук, структура, визуальное оформление, anti-AI-slop, фактчекинг |
| `guidelines/story-method.md` | **Для всех ниш.** Как искать истории и видео (2–6 мин, сильные первые секунды, тест досмотра) и структура поста по референсам автора. При расхождении со структурой в `post-format.md` приоритет у этого файла |
| `guidelines/content-producer.md` | Когда автор присылает исходник (видео, статью, интервью, ссылку): анализ → угол подачи → пост → визуал → источники |
| `guidelines/animations.md` | Только когда автор просит анимацию (AI / Tech): идея, сценарий, раскадровка, тех. параметры 1920×1080, 30 FPS, MP4 |
| `guidelines/quality-control.md` | Всегда — финальная редакторская проверка любого результата перед выдачей |
| `guidelines/hollywood-backstories.md` | **Только ниша 6 Hollywood Backstories.** О чём ниша, границы с другими, структура и оформление по референсам автора |
| `guidelines/dark-history-playbook.md` | **Только ниша Dark History.** Перенос механики интервью-постов: один момент вместо хроники, бытовая деталь-парадокс, 120–200 слов, первые 1–5 секунд видео. Важнее `story-method.md` для этой ниши |
| `guidelines/money-playbook.md` | **Только ниша Money Stories.** Перенос механики интервью-постов: выбор идеи, структура, хук, первые 1–5 секунд видео, чек-лист. Для этой ниши важнее `story-method.md` |
| `guidelines/interviews-playbook.md` | **Только ниша Interviews.** Плейбук по посту-эталону (~430к просмотров): выбор идеи, структура, хук, как заставить посмотреть видео, чек-лист |
| `examples/interviews/01-lexi-luna-rating.md` | **Эталон стиля для ниши Interviews** (только для неё) |
| `examples/real-life-stories/reference-posts.md` | **Истории людей из длинных интервью (Soft White Underbelly и т.п.).** Каркас по посту Harmonie + приёмы Scotch Dolly. Ссылаться на оба примера при написании |
| `examples/<ниша>/` | Референсные посты автора с разбором структуры и видео. Общая структура в `story-method.md` применяется ко всем нишам. Факты в референсах не образец: проверять |

## Ниши
1. AI / Tech — формат «история от первого лица», см. `guidelines/ai-first-person-format.md` (только для этой ниши)
2. Interviews
3. Dark History & Real-Life Stories
4. Money Stories About Famous People
5. Sports Stories — сам спорт: легендарные и конфликтные матчи, бои, рекорды, апсеты, спорные решения, суперсобытия (NFL, NBA, бокс/UFC в приоритете; раздел 7.5 в `post-format.md`). Истории про деньги и контракты спортсменов — это ниша 4
6. Hollywood Backstories — закулисные истории звёзд от первого лица (конфликты, украденные идеи, почти не случившиеся проекты, переломы, тайное прошлое). Правила: `guidelines/hollywood-backstories.md`, референсы: `examples/hollywood-backstories/`

## Ключевые правила (кратко, полная версия — в `guidelines/`)
- Посты на английском по умолчанию, если автор не попросил другой язык
- Хук — абзац-досье из нескольких коротких предложений (как в референсах), первое предложение самое сильное; обычный регистр, никогда не ALL CAPS
- После хука короткие абзацы по 1-2 предложения, пустая строка между ними
- Без точек в конце строк, без длинных и средних тире (— –), только дефис (-)
- Финал — один короткий вопрос, без вывода после него
- Никогда не выдумывать цитаты, цифры, даты, таймкоды, содержание видео
- Источники к идеям: сначала блок 🎬 Видео (прямые ссылки, длина, канал, официальный или перезалив), потом 📰 Статьи для фактчекинга. Поиск видео: `python3 -I tools/yt_search.py "запрос"` (подробно в `story-method.md`)

## Перед выдачей поста — всегда черновик и самопроверка
Сначала черновик для себя → проверка: это история или пересказ видео? (видео — максимум 1–3 строки, без них история должна держаться сама) → если пересказ, переписать по структуре `story-method.md` → только потом отдать автору. Подробно: `story-method.md`, раздел «Обязательный черновик и самопроверка»

## Формат выдачи постов автору
- Готовый текст поста всегда присылать внутри блока кода (```text … ```), чтобы его можно было скопировать одной кнопкой
- В блоке только сам пост, без заголовков, пометок и разделителей
- Комментарии, таймкоды для монтажа и замечания по проверке фактов писать вне блока
- Если вариантов поста несколько, каждый в отдельном блоке

## Как работать с репозиторием
1. Когда автор говорит «нужно изменить …» / «запомни …» — внеси правку в нужный файл
   в `guidelines/`, добавь запись в `CHANGELOG.md`, закоммить и запушь.
2. Не выдумывай правила, которых автор не давал. Если что-то не описано — спроси.
3. Когда автор присылает референсные посты — определи нишу и сохрани в `examples/<ниша>/`.
4. Если автор хвалит пост — предложи сохранить его в `examples/`.
